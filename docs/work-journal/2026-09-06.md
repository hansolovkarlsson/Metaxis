## The morning: a check for the documents, and what its first run found

The standup left one task-shaped item on the roadmap: run the `$ mx …`
transcripts in `docs/`, because the audit the night before had caught one
that was invented. The two decisions the item said were not obvious turned out
to settle themselves once the check was written rather than reasoned about.
Elision stays, because REFERENCE would be worse without it, and the check
learns that a line of `…` means *skip ahead to the next line that matches*;
and the check runs from the tree root, so documents keep writing paths that
way. A third decision the item had not foreseen came out of the first run:
trailing whitespace is stripped on both sides, because an editor strips it

the two `-g` transcripts could never have matched exactly. That was the first
thing running the transcripts found. The second was that the first transcript

rename had missed and no reader had noticed because the output under it was
right.

POSTMORTEM.md is excluded from the check by name, because it quotes the
invented transcript *as* the record of the mistake and must go on quoting it.
That is the one place a false transcript belongs, and a check that made it
impossible to keep one would be a check that erased the postmortem's

## Picking a fourth translator, and why BASIC

With that item gone the roadmap had run out of tasks, which the standup had
said was the result rather than a problem. The rule on the page is that the
next mechanic is picked by picking the translator that would ask for it. Hans
asked which translators had been considered so far, and the honest answer was
that none had been named: the records had two candidate *mechanics* from the
survey's shortlist, collection attributes and the island rule, and had never
taken the step the rule required.

Four suggestions, each tied to what it would ask for. BASIC → C for
collection attributes, because BASIC declares nothing and C wants every
variable declared first, so the head of the output is the aggregate of its
body and no rule can fake it. The tool rewriting its own C source for the
island rule, with the test being that the rewritten tree still passes its
suite. Markdown → troff for collections in text mode. And a typed language
for the declared environment, named as the door that closes, because
direction.md keeps that one last. Hans picked BASIC.

It was built by the stage 3 method: the BASIC program and its C written by
hand first, then the `.mx` file taken as far as the mechanics reached. They
reached all the way to the wall and no further, which was the prediction. Two
things in the notation did more than expected. A line number is the left
operand of an infix keyword — `10 LET T = 0` is the number ten followed by a
led rule whose word is `LET` — and a Pratt parser makes that of it without
being told. And the type of a BASIC variable is the sigil on its name, so
`replace(x, "$", "") != x` is *this is a string*, and the `writeln` wall that
stopped stage 1 was not met, by choice of source rather than by any mechanic.
The compiler earned its place on the first run: `END` is the last statement,
so no separator follows it, and its semicolon had to be its own. And `NOT T >
30` came out as `!T > 30` until the bracket threshold for `NOT` was raised to
one above the top of the ladder, because C's `!` binds tighter than anything
and BASIC's `NOT` binds looser than a comparison.

The wall arrived with a second face the survey had not named: BASIC has no
head. Pascal has `program` and a rule could splice an aggregate there. BASIC's
first line is a statement, so the *file* would have to be able to say *before
the first statement*, and nothing in the notation said that. That became the
second of three decisions on the roadmap item, and `tests/basic.sh` wrote the
four declarations by hand and pinned itself in both directions — the program
must not build without them, and the translator must not have started
writing them — so that the day the wall came down, the test would say so.

## The island, rehearsed rather than built

Hans asked about going for the island rule next. The recommendation was to
rehearse before planning, because text mode is already an island grammar —
the body is scanned, a rule fires where it matches, and everything else is
copied through — so the cheapest thing that tested the idea cost no tool
change at all. A five-line header over `metaxis/cmd/mx.c`, the tool's own
front end, turned six error-printing calls into `complain(err)` and inserted
the definition in front of `usage`, and the rewritten tree built and passed
every check. The survey's strongest finding, the one it said would change
what the tool could be pointed at, was already there.

What the rehearsal then measured, by running each thing rather than
predicting it, was where text mode falls short of a rewrite over real code.
Renaming `usage` also rewrote the word inside the usage string, and renaming
`err` turned `stderr` into `stde`: no tokens. A hole over `f(x, g(y))` stopped
at the first `)`, and was right only by accident, because the template kept
the hole last and the leftover text was copied through behind it; a template
that reused the hole was wrong: no brackets. Declaring C's comments so rules
would stop firing inside them deleted the comments from the output: text
mode's comment handling is right for a document and wrong for a rewrite that
has to give the file back. And a led rule in text mode was accepted and
silently never fired — `p->f` came through unchanged with exit 0 — which the
reference had described in one sentence and nothing had enforced. That last
one was fixed the same hour, at the same place the class-kind check lives.

The conclusion was not the one the survey had set up. Its three shapes for
islands were all for expression mode, and the rewrite asked for none of them.
What it wants is text mode plus the three things Comby knows — identifiers,
balanced brackets, and strings and comments skipped over rather than removed
— which is a smaller mechanic than any of the three and touches neither
expression mode nor its completeness. That is ROADMAP 7. The rehearsal was
then made permanent as stage 5: `lib/island.mx`, an example over four
representative lines, and `tests/island.sh`, which concatenates the rules
with the real `mx.c` at test time so they cannot drift, compiles what comes
out against the tree's own objects, and runs the binary.

## Collections, rehearsed with markers and then built

Roadmap 4 had three decisions and a falsifier: if the second pass that fills
in an aggregate ever had to know anything about the output language, the
agnosticism was spent and the feature was not worth it. Rather than design
against that, the whole mechanism was faked. Rules emitted `@@vars:int T;@@`
where a contribution would go and `@@splice:vars@@` where the aggregate
would, and a twelve-line awk pass over the output collected the distinct
contributions in first-seen order and replaced the splice. BASIC compiled and
ran without `basic.sh`'s hand-written prologue. Pascal got its include from
`writeln` and none in a copy with every `writeln` removed. The island spliced
the definition of `complain` at its landmark. The pass never looked between
the markers, so the falsifier did not fire, and the plan was written from
what the markers had done: a contribution is a complete line, deduplicated
by exact text in first-seen order; the file names the splice point; the start
of the output is the default only for a source with no head, which is right
for BASIC and would be wrong for C, where a definition must follow the
includes — and C did not need it, because the rewrite could name `usage`.

Then it was built in the shape rehearsed and nothing more. `contribute` is a
statement beside `emit`, not a keyword, because a name with `(` after it
where a statement was expected can be nothing but a call, so a hole may still
be called that. `splice` is an expression giving a placeholder, and the
placeholder is a fresh name, so the guarantee `{~t}` already had — occurs
nowhere in the source or any template — carries over without a new
mechanism. The pass carries the placeholder's leading whitespace onto every
following line of the aggregate, so a splice inside an indented block stays in
the block, and an empty aggregate alone on its line takes the line with it;
both are facts about the text and not about any language. `basic.sh`'s pin
flipped in the same commit, as it had said it would. Neither `code.out` nor
`island.out` changed by a byte. The transcript check caught the stage 4
COMPLETED entry, whose recorded output now began with four declarations —
which is the check doing the job it was built for that morning.

## The tutorial as a test

Hans asked for a manual or tutorial, because the concepts were novel and hard
to hold. It was written as sixteen sections, each with a small file under
`docs/tutorial/` written to show one sentence of the reference, and every
transcript pasted from a run, because the transcript check would have refused
anything else. That discipline paid within the hour. Lesson 5 wrote
`block … end` on one line and `while` on the next with no separator between,
because the reference had said since the first day that a statement ending in
a word needs none. It failed: `no rule reads 'while' here`. The check asked
whether the last token was *punctuation*, which `}` is and `end` is not — the
class wins a tie, so `end` lexes as a name — and every example in the tree had
written `end;`, Pascal's own idiom, so the sentence had never been exercised.
The parser now records the index of the last token a rule consumed *as a
word*, restores it wherever it restores the cursor, and asks that instead.
POSTMORTEM 21's learning is the general form: a translator writes its source
language the way its speakers do, so a corner that idiom never visits is
never visited, and a file written to demonstrate one sentence is the input
the suite did not have. `docs/tutorial/` is that, and the transcript check is
what makes it a test rather than prose.

The glossary followed, for the words the tutorial and the records use without
explaining — PEG, CFG, nud, led, attribute grammar, hygiene — as a short
account of the concepts in the order they depend on each other and then the

## A style rule, a check first, and eleven hundred dashes

Hans added a style guide to `CLAUDE.md`: no em dash in general prose, with a
comma, a period or a colon in its place, and then the exceptions, a dash that
is a fact, a quotation, a title, or code. The scoping came before any edit.
There were 1,146 in the tree on 1,052 lines, all prose: none in a `.mx` body,
an `.out`, a fenced transcript, or the tool's code, so the suite could not see
the change and no recorded output would move. The site's slug function strips
punctuation, so every heading kept its anchor under any substitution. What
made it a job rather than a substitution was that each of a thousand sentences
needed a choice, and the documents are hard-wrapped, so a change reflows a
paragraph.

The check was built before the sweep so that the sweep had a finish line the

tracked files, so awk was handed nothing, read an empty standard input, and
found no dash in it. That is the failure the limit guard's note in the same

the afternoon with the roadmap check, harmlessly that time. The scan now

## A page of languages, and the two verdicts the tool overturned

Hans asked for a list of the languages and tools Metaxis is fit for and a
list of those it is not, with the reason for each, covering the common ones.
None of the six documents about the thing had that job: the survey scores
tools, the direction page declines C and Python front ends in one paragraph,
and the reference states properties without saying which language each one
stops. So it became a seventh, `docs/languages.md`, and the method was the
survey's: state the properties first, then rest every verdict on one of them,
so that a language not on the page can be scored the same way.

Seven properties came out of the reference and the direction page, and each
was run against the tool before it was written down, in scratch files that
were thrown away. Four confirmed what the documents say: words are
case-sensitive, block comments do not nest, a class that could match the rest
of a line swallows the keyword in front of it, and a rule that begins with a
hole must have a word second. Two overturned what this page's author had
assumed. The first was Lisp. `"(" f:name [ x ]* ")"` looked like the shortest
grammar on the page and the header refused it: a repeated group whose turns
are expressions needs a `sep` word to know where a turn stops, and whitespace
is never a word. So an argument list separated by nothing is unreadable in
expression mode, and the language famous for having no syntax is on the unfit
list for that reason, together with ML application, shell command lines and
the tool's own EBNF. The second was XML. A class for character data, `[^<>]+`,
is the longest match at the position after `<` as well, so it swallowed the
tag name. Character data is a token only by where it stands, which is lexer
state, and XML reads whole only when it has no text in it. Both are on the
page with the day they were run.

What the page adds to the direction page's one paragraph is the middle: the
languages that are fit as a subset, and where each subset stops. Pascal,
Python and Lua are there with the property that stops them named, and the
fixed-shape formats are there with the one line that says a wrapped value is
the roadmap's second item. The jobs table at the foot reads the same seven
properties by task rather than by language, since that is the shape of the
question a reader usually has.
