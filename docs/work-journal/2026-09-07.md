## The splice bug, and what the fresh name guards against

`pt_fresh` makes a mark that occurs nowhere in the source and in no
template, by a substring test that is conservative in the safe direction:
`t__1` is refused while `t__12` is in the file. What it was never asked
about is the other marks. Ten collections make ten marks, and the pass
that replaces them matched each against the output with `strncmp` over
the mark's own length, taking the first that matched. The fix is to take
the longest, since a shorter mark that matches at a position is a prefix
of the longer one that also does. Reproduced before the fix with ten
`splice`s and one `contribute` to the tenth, `foo` then `|0|` where
`|foo|` was wanted, and pinned in `tests/basic.sh`, which is the
collections' test, with the ten-collection file written into the script.
The case fails on the old code with the wrong output shown. Nothing in
`examples/` has ten collections, which is why the suite had not seen it.
POSTMORTEM 31.

## The site builder: a hang, a nesting, and a numbering

The list loop matched an indented item as the start of a list and then,
inside, matched only unindented items, so an indented item that opened a
list matched nothing and the loop never advanced. The docs already had
indented items under a parent, the four consequences of the lexer property
on the languages page, and those had been folding into the parent's text
as one paragraph with literal dashes in it. So the fix was one level of
nesting, with the first line of a list always matching the first branch so
the loop always moves. Every page was rendered before and after and
diffed; only the languages page changed, in that one place.

The same loop had a second fault seen while fixing the first: a blank line
between items ended the list, so the seven properties on the languages
page were seven lists each numbered 1. A blank line keeps the list now
when the next non-blank line is an item of the same kind, or a sub-item.
Rendered and diffed again: only the languages page changed, eight `ol`
becoming two. The before-and-after diff of every page is what made both
changes safe to make in a script the suite does not run.

## One caption regex, and the dialect it had to be written in

`tests/docs.sh` and `site/build.py` each kept a copy of the regex that
recognises a caption line, and they had drifted: Python's `\w` admits
non-ASCII and the site kept a caption across a paragraph while the check
dropped it. The most flexible fix is one source the other reads, and the
question was which. The site is the thing that renders the caption, so
`build.py` holds `LABEL` on one line in a dialect awk reads too, and

a `-v` assignment processes escape sequences and would have eaten the
`\.`. Both scripts now drop a caption that a paragraph separates from its
fence. The check still finds 25 quoted files, and renaming the constant
in a copy of `build.py` makes the check fail by name.
